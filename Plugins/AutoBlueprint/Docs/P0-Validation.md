# P0 代码与本地验证

实现状态：P0 源码已准备，UE 5.3.2 的编译与运行验证待本地完成。云端没有 UE Editor，尚未生成或提交测试 `.uasset`，P0 未标记为验收通过。

## 1 编译并运行

1. Fetch 并切换到 `feature_auto_blueprint_plugin`，关闭正在运行的编辑器。
2. 右键 `ProjectOne.uproject`，重新生成 Visual Studio 工程文件。
3. 使用 UE 5.3.2 编译 `ProjectOneEditor / Development Editor / Win64`。新增了反射类型，首次编译使用完整构建，然后重新启动编辑器。
4. 打开 **Output Log（输出日志）**，在底部控制台输入以下命令。执行生成时保持普通编辑状态，无需点击 Play。

```text
AutoBlueprint.P0.Generate /Game/UI/AutoBlueprintTests/WBP_P0_Review01
```

命令必须提供一个明确的新包名。`ProjectOne.uproject` 已为 Editor 目标启用 AutoBlueprint，插件声明依赖项目已有的 UnLua。无需安装 Python 插件或修改 Engine/UnLua 源码。

成功时日志应包含 `Saved package:`、`Generated:` 和 `P0 Lua task completed`。目标文件应为 `Content/UI/AutoBlueprintTests/WBP_P0_Review01.uasset`；在 Content Browser 中打开该 Widget Blueprint。

## 2 检查控件树和持久化

```text
RootCanvas                 CanvasPanel  Is Variable = false
├─ TXT_Title               TextBlock    Is Variable = true
└─ BTN_Confirm             Button       Is Variable = true
   └─ TXT_Confirm          TextBlock    Is Variable = true
```

| 节点 | 固定输入与布局 |
| --- | --- |
| TXT_Title | 文本 `AutoBlueprint P0 - generated by Lua`；Canvas 位置 `(64, 64)`，尺寸 `(512, 48)` |
| BTN_Confirm | Canvas 位置 `(64, 160)`，尺寸 `(240, 64)`；使用原生默认按钮样式 |
| TXT_Confirm | 文本 `Confirm`；Button Slot 水平/垂直居中；Padding 左右 12、上下 8 |

Canvas 子节点锚点和 Alignment 均为左上 `(0, 0)`，AutoSize 为 false。文本为白色、不可命中测试。P0 使用引擎默认字体；Designer 可选择 1280 × 720 预览，插件尚未实现 JSON 的设计尺寸设置。

检查标题、按钮、父子层级，以及三个显式变量。然后**关闭整个编辑器，再重新启动并打开同一资产**，确认上述内容仍存在。不要在重开时再次运行 Generate 来代替磁盘重载检查。

## 3 重复执行与失败检查

| 操作 | 预期结果 |
| --- | --- |
| 再次生成 `WBP_P0_Review01` | 返回 `ASSET_ALREADY_EXISTS`，保留原资产和人工修改 |
| 改用 `WBP_P0_Review02` | 独立生成新资产；证明后续任务可继续运行 |
| 路径使用 `/Game/UI/Other/WBP_P0` 或包含 `.uasset` | 返回 `INVALID_PACKAGE_PATH`，不创建目标包 |
| 先手工创建同名 Widget Blueprint，但不保存，再运行生成 | 返回 `ASSET_ALREADY_EXISTS`，保留内存中的资产 |
| Play 或 Simulate 期间执行生成 | 返回 `EDITOR_BUSY`；停止后可正常重试 |
| 执行下列错误探针，再使用新名称生成 | 探针报错有脚本路径、行号和调用栈；后续生成可正常运行 |

```text
AutoBlueprint.P0.ErrorProbe
```

错误探针故意抛出 `AUTOBLUEPRINT_P0_EXPECTED_ERROR`，应看到 `LUA_SCRIPT_FAILED` 和 `p0_error.lua` 的调用栈。探针不调用资产生成 API。

如需检查同名生成是否改写磁盘，可在重复命令前后对目标 `.uasset` 执行 PowerShell `Get-FileHash` 并比较。这里仅用于检查“拒绝生成时没有改写已有文件”，不用于判断两次独立生成的资产是否等价。

## 4 自动化检查

在普通编辑状态的 Output Log 执行：

```text
Automation RunTests AutoBlueprint.P0
```

也可在 Session Frontend 的 Automation 页面选择 `AutoBlueprint.P0`。当前有三项 UE 测试，均不写 `.uasset`：

- `InputValidation`：无效路径、空文本被拒绝，验证不分配目标包。
- `LoadedPackageConflict`：同名未保存包被拒绝，原对象及 dirty 状态保持。
- `LuaErrorAndCleanup`：连续异常保留堆栈、真实反射调用的构建失败传回宿主；任务前后的 Lua 环境数量、既有环境和游戏 Lua 启用状态保持。

实际成功生成、保存和新会话重开仍按前述步骤检查。上述 UE 测试已编写，尚未在云端运行。

另外提供独立 Lua 脚本测试，从仓库根目录运行：

```text
lua Plugins/AutoBlueprint/Scripts/Tests/p0_scripts_test.lua
```

云端使用仓库附带的 Lua 5.4.3 源码临时构建了解释器，9 项脚本流程检查通过，涵盖成功、保存失败、布尔契约、编译/保存状态不一致、异常和无效脚本入口。该测试使用模拟的 UE 接口，只验证 Lua 流程，不证明 UnLua 反射、C++ 编译或资产生成可用。正常使用插件不需要额外安装独立 Lua。

## 5 代码入口和当前边界

| 文件 | 作用 |
| --- | --- |
| [AutoBlueprintEditorModule.cpp](../Source/AutoBlueprintEditor/Private/AutoBlueprintEditorModule.cpp) | 注册和注销两个 P0 控制台命令 |
| [EditorLuaRunner.cpp](../Source/AutoBlueprintEditor/Private/Scripting/EditorLuaRunner.cpp) | 每次任务创建独立 `UnLua::FLuaEnv`，通过公开 `DoString` 执行并释放环境 |
| [p0_generate.lua](../Scripts/Lua/p0_generate.lua) | 固定输入、结构体参数、诊断及布尔返回值检查 |
| [AutoBlueprintLibrary.h](../Source/AutoBlueprintEditor/Public/AutoBlueprintLibrary.h) | Lua 可调用的静态反射门面 |
| [AutoBlueprintSubsystem.cpp](../Source/AutoBlueprintEditor/Private/AutoBlueprintSubsystem.cpp) | 上下文/输入/CreateOnly 校验与构建调度 |
| [SmokeTestWidgetTree.cpp](../Source/AutoBlueprintEditor/Private/Widgets/SmokeTestWidgetTree.cpp) | 构造资产模板的固定控件树 |
| [WidgetBlueprintWriter.cpp](../Source/AutoBlueprintEditor/Private/Assets/WidgetBlueprintWriter.cpp) | 检查编译诊断并按请求保存 |
| [AutoBlueprintTypes.h](../Source/AutoBlueprintEditor/Public/AutoBlueprintTypes.h) | 请求、构建结果和诊断的反射契约 |

`BuildSmokeTestWidget` 为 P0 固定样例接口。架构中的 `ValidateLayoutFile`、`BuildFromLayoutFile`、JSON Schema 和控件注册表仍属于 P2/P3，尚未实现。固定树代码单独放置，后续复用门面、子系统、诊断、编译保存流程，再接入通用构建器。

P0 的两份脚本是独立模块，不使用 `require`。宿主只接受这两个固定文件，执行前清空该任务环境的模块搜索路径；通用受控模块加载留到 P1。UnLua 自身的环境初始化仍会执行其内置初始化和已注册回调，工具不调用游戏的 `Start`/`SetActive`，不执行项目默认启动模块。该入口用于可信的项目工具脚本，不提供不可信代码沙箱。

`bSave=false` 表示“生成并编译，但不落盘”，会留下新建的未保存资产，不能当作只读预检。同名重试仍会被拒绝。编译/保存失败也可能留下本次创建的未保存包，`UnsavedPackages` 会报告这些包；插件不自动删除用户资产。Lua 脚本在保存后再报错时，先前的保存结果仍有效，`Saved package:` 日志保留，不承诺回滚。
